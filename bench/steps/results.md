# steps adapter benchmark

Run on 2026-09-25 with Jev (`jev-1.13.0`), 28 labeled agent histories (`bench/steps/`, generated by `make_data.py`), 3 runs per history and arm.
- **Histories:** 10 to 30 tool calls by a coding agent working on GitHub, using real tool names from GitHub's MCP server. Each starts with ordinary exploration and ends in one of four ways.
- **Labels:** 8 stuck repeating, 7 stuck failing, 8 progressing, and 5 done.

| Arm | Accuracy | Median input tokens | Median latency (ms) | Median confidence |
|---|---|---|---|---|
| raw (every step, no counting) | 89% (75/84) | 2,506 | 347 | 0.94 |
| jevbrief (counted signals + last 6 steps) | **93% (78/84)** | **1,266** (−49%) | 344 | 0.96 |

A run is correct when Jev's verdict (`progressing`, `stuck_repeating`, `stuck_failing`, or `done`) matches the label. Two histories accept two verdicts, for example "done" or "stuck repeating" for an agent that found the answer and kept searching.

## Where the arms differ

- **jevbrief right, raw wrong (1 history):** the agent searched once with no result, searched again with new terms, found the file, and read it. The raw arm called this `done`. jevbrief said `progressing`: the goal was to find the code, and the agent had just opened it. Both readings are arguable, and the label is `progressing`.
- **Both wrong, and the labels are arguable (2 histories):**
  - "Read the payments module": `get_file_contents` returned "Not Found" five times as a result, not an error. It is labeled stuck repeating, and both arms said stuck *failing*, which is also reasonable.
  - "Open a pull request with the invoice fix": the first try returned a 502 error, the retry created PR #92, and the agent then requested a review. It is labeled progressing, and both arms said *done*. The pull request does exist, so this label is probably wrong. It was kept as written, because the labels were fixed before the run.

## Counting alone

`loop_signals`, with no Jev call, flags a loop whenever it returns anything. That rule separates stuck from not stuck on all 28 histories. In this set, the counting does most of the work. Jev adds:
- the four-way verdict: done against progressing, and failing against repeating
- advice: change arguments, try a different tool, or ask the user
- a confidence

Use `loop_signals` on every step, and `check_progress` when it returns something.

## Caveats

- **Synthetic histories.** They were written while building the adapter, alongside the counting rules. The endings include cases built to look like loops but be progress (paging, polling, a retry that works), and cases built to look busy but be stuck (new search terms that keep finding nothing). Real agent traces will be messier.
- **Real data so far:** one real stuck history, the NES demo's trace, where the counting finds "jump_right called 20 times in a row". Please contribute real stuck agent traces.
